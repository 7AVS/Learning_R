Words & denominators

Ratio — one group's share of the leavers divided by its share of the stayers. 1.00 = equally common in both. Never a headcount, never a chance of leaving.

UCP — the bank's client profile table: age, tenure, product counts, profitability. "UCP-matched" = we found that client in it.

Quintile — the population sorted by a value, cut into five equal-sized groups.

Denominator — whatever a percentage divides by. It changes by section and is named each time.

Artefact — a pattern produced by how we mailed or measured, not by the clients.

Solo rate — a campaign's unsubscribe rate measured on its own.

Exposure vs attribution — two ways to count a campaign's unsubscribes. §4; they differ 4.6× on the same campaign.

Three-letter codes are campaign mnemonics. The cards five: PCQ, PCL, PCD, AUH, CRV.

Caveats that govern every number

Which unsub rate. 0.66% divides by everyone mailed. 0.68% divides by everyone who was able to unsubscribe — excluding the 427,079 already opted out, who were never at risk of leaving again. 0.68% is the one to quote, and every table here follows that rule.

UCP match rate is 89.7% of stayers, 90.1% of leavers, 97.8% of the already-out group — not one band. Worst field 0.01% null.

Who goes unmatched: business programs (SBB: 2,274 leavers, 0 matched) and clients acquired during the window, who cannot exist in a 2026-02-28 snapshot. Every percentage uses the matched denominator.

No significance test was run anywhere on this page. Phrases like "too small to act on" are judgements from group sizes, not test output. Compute the interval before any of these numbers carries a decision.

-- §1  LEAVER vs STAYER, bank-wide.  Museum cell [19], "L7".
-- One row per (dimension, value). ratio > 1 = over-represented among leavers.
WITH pop AS (
    SELECT CLNT_NO, bucket, age_band, tenure_band, prod_band, prof_quintile, high_potential
    FROM   client_spine
    WHERE  ucp_matched = TRUE          -- unmatched have no bands and must not dilute a %
),
denom AS (
    SELECT SUM(CASE WHEN bucket = 'leaver' THEN 1 ELSE 0 END) AS n_leavers,
           SUM(CASE WHEN bucket = 'stayer' THEN 1 ELSE 0 END) AS n_stayers
    FROM   pop                          -- already_out is in NEITHER: see §5
),
long AS (                               -- unpivot: one row per client per dimension
    SELECT bucket, 'age_band'       AS segment_dim, age_band       AS segment_value FROM pop
    UNION ALL
    SELECT bucket, 'tenure_band',      tenure_band      FROM pop
    UNION ALL
    SELECT bucket, 'prod_band',        prod_band        FROM pop
    UNION ALL
    SELECT bucket, 'prof_quintile',    prof_quintile    FROM pop
    UNION ALL
    SELECT bucket, 'high_potential',   CAST(high_potential AS VARCHAR) FROM pop
)
SELECT  l.segment_dim,
        l.segment_value,
        SUM(CASE WHEN l.bucket = 'leaver' THEN 1 ELSE 0 END)              AS leavers_n,
        SUM(CASE WHEN l.bucket = 'stayer' THEN 1 ELSE 0 END)              AS stayers_n,
        100.0 * SUM(CASE WHEN l.bucket='leaver' THEN 1 ELSE 0 END) / d.n_leavers AS pct_leavers,
        100.0 * SUM(CASE WHEN l.bucket='stayer' THEN 1 ELSE 0 END) / d.n_stayers AS pct_stayers,
        (100.0 * SUM(CASE WHEN l.bucket='leaver' THEN 1 ELSE 0 END) / d.n_leavers)
      / (100.0 * SUM(CASE WHEN l.bucket='stayer' THEN 1 ELSE 0 END) / d.n_stayers) AS ratio
FROM    long l CROSS JOIN denom d
WHERE   l.bucket IN ('leaver','stayer')
GROUP BY l.segment_dim, l.segment_value, d.n_leavers, d.n_stayers
ORDER BY l.segment_dim, ratio DESC;

-- BAND DEFINITIONS - our choice, not a standard. Edit in cell [16] and nowhere else.
--   age_band     <25 / 25-34 / 35-44 / 45-54 / 55-64 / 65+
--   tenure_band  0-2 / 3-5 / 6-10 / 11-20 / 20+     (TENURE_RBC_YEARS)
--   prod_band    0 / 1 / 2 / 3-4 / 5+               (T_TOT_CNT+I_TOT_CNT+B_TOT_CNT+C_TOT_CNT)
--   high_pot     AGE < 35 AND TENURE <= 5 AND prod_cnt <= 2

-- §2  PROFITABILITY QUINTILES.  Museum cells [16] + [19].
-- Cut points come from the MAILED BASE, not from leavers, so "top quintile" is defined
-- relative to the reachable population rather than relative to the people who left.
WITH cuts AS (
    SELECT APPROX_PERCENTILE(PROF_TOT_ANNUAL, 0.20) AS p20,
           APPROX_PERCENTILE(PROF_TOT_ANNUAL, 0.40) AS p40,
           APPROX_PERCENTILE(PROF_TOT_ANNUAL, 0.60) AS p60,
           APPROX_PERCENTILE(PROF_TOT_ANNUAL, 0.80) AS p80
    FROM   client_spine
    WHERE  ucp_matched = TRUE AND PROF_TOT_ANNUAL IS NOT NULL
),
q AS (
    SELECT s.bucket,
           CASE WHEN s.PROF_TOT_ANNUAL IS NULL   THEN 'unknown'
                WHEN s.PROF_TOT_ANNUAL <= c.p20  THEN '1'
                WHEN s.PROF_TOT_ANNUAL <= c.p40  THEN '2'
                WHEN s.PROF_TOT_ANNUAL <= c.p60  THEN '3'
                WHEN s.PROF_TOT_ANNUAL <= c.p80  THEN '4'
                ELSE '5' END AS prof_quintile
    FROM   client_spine s CROSS JOIN cuts c
    WHERE  s.ucp_matched = TRUE
)
SELECT prof_quintile,
       SUM(CASE WHEN bucket='leaver' THEN 1 ELSE 0 END) AS leavers_n,
       SUM(CASE WHEN bucket='stayer' THEN 1 ELSE 0 END) AS stayers_n
FROM   q
WHERE  bucket IN ('leaver','stayer')
GROUP BY prof_quintile
ORDER BY prof_quintile;
-- ratio = (leavers_n / total_leavers) / (stayers_n / total_stayers), as in §1.

-- OBSERVED CUT POINTS, run 2026-07-29:  p20 = -166.72   p40 = -2.37   p60 = 372.71   p80 = 1,473.07

3. We lose the people who were still reading

Every client classified by what they did with our email before the window closed: clicked, opened without clicking, or never opened. Ratio compares each group's share of leavers against its share of stayers.

Clients who click are over-represented among leavers at 1.51×. Clients who never open are under-represented at 0.43×. People who stopped reading rarely unsubscribe — 9.86% of leavers came from that group, against 74.19% from openers. They do still leave: 6,180 of them did. The pattern is that unsubscribing tends to be something an attentive client does, not the final act of someone who had already tuned out.

The larger number is the one nobody counts. 2,073,020 stayers — 22.85% of the stayer pool — did not open a single email in three months. That silent population is roughly 30× the size of everyone who explicitly unsubscribed. We report the 69,535 and not the 2 million.

Engagement is measured, not assumed — from the client's own sends in the window.

-- §3  ENGAGEMENT BEFORE LEAVING.  Museum cell [20e], "L11".
-- disposition_cd on VENDOR_FEEDBACK_EVENT:  1 = sent   2 = opened   3 = clicked   4 = unsubscribed
-- Engagement is classified from the SAME window as the outcome, per client, across all campaigns.
WITH eng AS (
    SELECT m.CLNT_NO,
           MAX(CASE WHEN e.disposition_cd = 2 THEN 1 ELSE 0 END) AS opened,
           MAX(CASE WHEN e.disposition_cd = 3 THEN 1 ELSE 0 END) AS clicked
    FROM   DTZV01.VENDOR_FEEDBACK_EVENT e
    JOIN   DTZV01.VENDOR_FEEDBACK_MASTER m
          ON m.consumer_id_hashed = e.consumer_id_hashed AND m.TREATMENT_ID = e.TREATMENT_ID
    WHERE  e.disposition_cd IN (1,2,3)
      AND  e.disposition_dt_tm >= DATE '2026-03-01' AND e.disposition_dt_tm < DATE '2026-06-01'
    GROUP BY m.CLNT_NO
)
SELECT s.bucket,
       CASE WHEN g.clicked = 1 THEN 'clicked'
            WHEN g.opened  = 1 THEN 'opened_not_clicked'
            ELSE                    'never_opened' END        AS engagement,
       COUNT(*)                                               AS clients,
       100.0 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY s.bucket) AS pct_of_bucket
FROM   client_spine s JOIN eng g ON g.CLNT_NO = s.CLNT_NO
WHERE  s.ucp_matched = TRUE
GROUP BY s.bucket, 2;
-- ratio = leaver pct_of_bucket / stayer pct_of_bucket.

-- WHY "never_opened" IS NOT THE SAME AS "did not receive". Apple Mail Privacy Protection fires the
-- open pixel without a human, which INFLATES opens. A zero-open client is therefore a strong signal,
-- not a weak one: they did not open even by accident. The 0.43 ratio is if anything understated.
--
-- click_without_open is EXPECTED and is not a data error - image blocking kills the open pixel while
-- the click still registers. That is why 'clicked' is tested before 'opened'.

Clients each campaign emailed who then unsubscribed from anything, per 1,000 mailed. Volume differs by 5× across these campaigns, so read the rate, not the count.

-- §3  TWO DIFFERENT RATES THAT LOOK LIKE ONE.  Museum cells [18] (L6) and [20b] (L9).

-- (a) EXPOSURE  - the number ON THIS PAGE.
--     "How many clients that CRV mailed went on to unsubscribe from anything?"
SELECT  cs.mne,
        COUNT(*)                                                   AS mailed_clients,
        SUM(CASE WHEN cs.bucket = 'leaver' THEN 1 ELSE 0 END)      AS leavers_exposed,
        1000.0 * SUM(CASE WHEN cs.bucket = 'leaver' THEN 1 ELSE 0 END) / COUNT(*)
                                                                   AS exposed_per_1000
FROM    senders_cards cs                 -- one row per (client, cards campaign)
WHERE   cs.ucp_matched = TRUE
GROUP BY cs.mne;

-- (b) ATTRIBUTION - the number in the notebook's L6 and in the campaign CSV.
--     "How many unsubscribes came THROUGH a CRV email?"
--     The unsub event carries the TREATMENT_ID of the send it was triggered from.
SELECT  SUBSTR(e.TREATMENT_ID, 8, 3)      AS mne,      -- positions 8-10 = campaign mnemonic
        COUNT(DISTINCT m.CLNT_NO)         AS unsubs_attributed
FROM    DTZV01.VENDOR_FEEDBACK_EVENT e
JOIN    DTZV01.VENDOR_FEEDBACK_MASTER m
       ON  m.consumer_id_hashed = e.consumer_id_hashed
       AND m.TREATMENT_ID       = e.TREATMENT_ID
WHERE   e.disposition_cd = 4                           -- 4 = unsubscribed
  AND   e.disposition_dt_tm >= DATE '2026-03-01'
  AND   e.disposition_dt_tm <  DATE '2026-06-01'
GROUP BY 1;

-- WHY THEY DIVERGE. TREATMENT_ID = TACTIC_ID = mnemonic + julian date, unique per deployment
-- wave. A client on nine lists who unsubscribes once is ATTRIBUTED to exactly one campaign but
-- is EXPOSED in all nine. Heavy senders inherit exposure blame they did not necessarily earn.
--
-- TO GET A RATE FROM THIS PAGE'S TABLE:  leavers / (leavers + stayers).
-- NOT leavers / mailed. `mailed` includes the already_out population (§5), who had already gone
-- and were never at risk of leaving again - they belong in neither numerator nor denominator.

-- §4b  CAMPAIGN CO-OCCURRENCE.  Museum cell [20g], "L13".  Basis: BANK_WIDE_SAMPLED.
--
-- THE POPULATION IS STRATIFIED, NOT RANDOM. Leavers are rare (70,425) and are taken WHOLE - no
-- sampling on the thing being measured. Stayers are 10.1M and only provide a baseline, so 1 in 10:
--      WHERE MOD(CLNT_NO, 10) = 0                    -- stayer sample
--         OR client has an unsubscribe in the window -- every leaver, unsampled
-- Weight 1 for a leaver, 10 for a sampled non-leaver. Weighting the leaver side too would inflate
-- the numerator and hand back the sampling rate as if it were a finding.
WITH pairs AS (
    SELECT a.CLNT_NO, a.mne AS mne_a, b.mne AS mne_b, s.bucket
    FROM   senders_wide a
    JOIN   senders_wide b ON b.CLNT_NO = a.CLNT_NO AND a.mne < b.mne   -- a < b = each pair once
    JOIN   client_spine  s ON s.CLNT_NO = a.CLNT_NO
)
SELECT mne_a, mne_b,
       SUM(CASE WHEN bucket = 'leaver' THEN 1 ELSE 10 END)  AS clients_est,
       SUM(CASE WHEN bucket = 'leaver' THEN 1 ELSE 0  END)  AS leavers_raw,
       1000.0 * SUM(CASE WHEN bucket='leaver' THEN 1 ELSE 0 END)
              / SUM(CASE WHEN bucket='leaver' THEN 1 ELSE 10 END) AS unsub_per_1000_est
FROM   pairs
GROUP BY mne_a, mne_b;
-- lift_vs_worse_solo = pair rate / GREATEST(solo rate of a, solo rate of b).
-- Compared against the WORSE of the two, not the average: a pair that only beats the weaker
-- campaign has told you which one is worse, not that the combination did anything.

5. Does a campaign lose single-product clients, or just mail them?

The fairness test. For each cards campaign: the share of single-product clients among everyone it mailed, against their share among the clients it lost.

share of clients mailed share of clients lost
43.7% of PCQ's leavers hold one product, which looks alarming until you see PCQ mails single-product clients at 36.8%. A +6.9pp gap is real but it is a fraction of the raw number. Most of what looks like "PCQ loses shallow clients" is "PCQ is an acquisition campaign and mails shallow clients."

Why single-product matters: for a client holding one product, email is often the only live channel. The gap column — not the raw share — is what is left after targeting is accounted for. On that measure PCQ (+6.9pp) and AUH (+5.8pp) lose depth-poor clients faster than they mail them; PCL (−1.8pp) and CRV (−1.4pp) do the reverse.

Show the logic (SQL)

The delta is the whole point. Either share alone is a targeting artefact.

-- §4  TARGETING vs LOSS.  Museum cell [20], "L8".
-- The same statistic computed on two populations that share a denominator definition, so the
-- DIFFERENCE isolates the campaign's own effect from who the campaign chose to mail.
SELECT  mne,
        COUNT(*)                                                          AS mailed_clients,
        SUM(CASE WHEN bucket = 'leaver' THEN 1 ELSE 0 END)                AS leaver_clients,

        100.0 * AVG(CASE WHEN prod_band = '1' THEN 1.0 ELSE 0.0 END)      AS mailed_pct_1prod,

        100.0 * SUM(CASE WHEN bucket='leaver' AND prod_band='1' THEN 1 ELSE 0 END)
              / NULLIF(SUM(CASE WHEN bucket='leaver' THEN 1 ELSE 0 END),0) AS leaver_pct_1prod,

        (100.0 * SUM(CASE WHEN bucket='leaver' AND prod_band='1' THEN 1 ELSE 0 END)
               / NULLIF(SUM(CASE WHEN bucket='leaver' THEN 1 ELSE 0 END),0))
      - (100.0 * AVG(CASE WHEN prod_band='1' THEN 1.0 ELSE 0.0 END))       AS delta_pp
FROM    senders_cards
WHERE   ucp_matched = TRUE
GROUP BY mne
ORDER BY mailed_clients DESC;

-- HOW TO READ delta_pp
--   > 0  the campaign loses single-product clients FASTER than it mails them  -> campaign effect
--   ~ 0  the loss mirrors the targeting                                       -> no campaign effect
--   < 0  it loses them SLOWER than it mails them
--
-- The raw leaver share on its own says almost nothing: an acquisition campaign mails shallow
-- clients by design, so of course its leavers are shallow. Only the gap is the campaign's doing.

6. The number nobody asked about: 427,079

Clients emailed in Mar–May who had already unsubscribed before the window opened. Not a finding about leavers — a finding about the suppression list.

427,079 clients — 4.03% of everyone mailed, and 6.1× the number who unsubscribed during the window — received email after opting out. They are excluded from the stayer pool throughout this page: they were not reachable, so counting them as having "chosen to stay" would be false, and counting them in a rate denominator would deflate every number by ~4%.

How long after opting out were they mailed:

Whatever this is, a processing delay does not explain it. 181,182 clients — 43.4% — were mailed more than a year after unsubscribing, 6.74 emails each on average. Only 5.8% sit in the 0–30 day window where a suppression lag would live.
DO NOT call this a suppression failure yet — some of these sends are allowed to be here. An unsubscribe withdraws marketing consent. Regulatory and servicing mail bypasses it by design and is supposed to reach an opted-out client. Every send here carries a campaign mnemonic, which rules out pure transactional mail — but a campaign can itself be regulatory, so the mnemonic does not settle it. Until the sends are split, 427,079 is the size of a question, not the size of a breach.

What we know so far. The known regulatory mnemonics are FXR, OTC, VMF and VOA, and none of them appears in the top 25 below — VRE, VME and VRG lead it, and VMB is a different mnemonic from VMF. But that table names the campaign each client left through, not the campaigns that mailed them afterwards, and it is the second set the regulatory question turns on. That breakdown does not exist yet — it is cell [20i], written and not run.

It concentrates around one campaign — but be careful what that means. 237,653 of these clients (56.9%) last unsubscribed through a VRE email, and were mailed again a median of 417 days later. Cards is a small share: PCQ 8,612, PCL 5,062, PCD 1,956 — 15,630 in total, 3.7% of the leak.

"Left through VRE" is not "VRE is at fault." The campaign a client unsubscribed through and the campaign that mailed them afterwards are two different things, and this table only shows the first. VRE may be recording the opt-out perfectly while other campaigns fail to read it — in which case naming VRE would point the investigation at the wrong team. What the skew does establish is that this is overwhelmingly not a Cards problem, and that VRE's unsubscribers are the population to trace first.

Open question for the room: is a VRE unsubscribe writing to a suppression list that other campaigns never read, or is it not writing at all? Those have different owners and different fixes, and nothing in this dataset separates them.

-- §6  THE ALREADY-OUT POPULATION.  Museum cells [13] and [20f], "L12".
-- Buckets are mutually exclusive and exhaustive over everyone mailed in the window.
WITH mailed AS (        -- every client sent at least one email, Mar-May 2026
    SELECT DISTINCT m.CLNT_NO
    FROM   DTZV01.VENDOR_FEEDBACK_EVENT e
    JOIN   DTZV01.VENDOR_FEEDBACK_MASTER m
          ON m.consumer_id_hashed = e.consumer_id_hashed AND m.TREATMENT_ID = e.TREATMENT_ID
    WHERE  e.disposition_cd = 1
      AND  e.disposition_dt_tm >= DATE '2026-03-01' AND e.disposition_dt_tm < DATE '2026-06-01'
),
unsub_in AS (           -- unsubscribed DURING the window
    SELECT DISTINCT m.CLNT_NO FROM DTZV01.VENDOR_FEEDBACK_EVENT e
    JOIN   DTZV01.VENDOR_FEEDBACK_MASTER m
          ON m.consumer_id_hashed = e.consumer_id_hashed AND m.TREATMENT_ID = e.TREATMENT_ID
    WHERE  e.disposition_cd = 4
      AND  e.disposition_dt_tm >= DATE '2026-03-01' AND e.disposition_dt_tm < DATE '2026-06-01'
),
unsub_before AS (       -- unsubscribed BEFORE it. Floor 2024-01-01: house rule, no scan below 2024.
    SELECT m.CLNT_NO,
           MAX(CAST(e.disposition_dt_tm AS DATE)) AS last_prior_unsub_dt,
           -- argmax in one pass: a fixed-format date sorts lexically as it sorts chronologically,
           -- so MAX(date || mne) carries the LAST unsub's mnemonic at positions 11-13.
           SUBSTR(MAX(CAST(CAST(e.disposition_dt_tm AS DATE FORMAT 'YYYY-MM-DD') AS CHAR(10))
                      || SUBSTR(e.TREATMENT_ID, 8, 3)), 11, 3) AS last_prior_unsub_mne
    FROM   DTZV01.VENDOR_FEEDBACK_EVENT e
    JOIN   DTZV01.VENDOR_FEEDBACK_MASTER m
          ON m.consumer_id_hashed = e.consumer_id_hashed AND m.TREATMENT_ID = e.TREATMENT_ID
    WHERE  e.disposition_cd = 4
      AND  e.disposition_dt_tm >= DATE '2024-01-01' AND e.disposition_dt_tm < DATE '2026-03-01'
    GROUP BY m.CLNT_NO
)
SELECT CASE WHEN i.CLNT_NO IS NOT NULL THEN 'leaver'        -- mailed AND left in window
            WHEN b.CLNT_NO IS NOT NULL THEN 'already_out'   -- mailed, but had left BEFORE it
            ELSE                            'stayer'        -- mailed, no unsub at all
       END                                          AS bucket,
       b.last_prior_unsub_mne                       AS left_via_mne,
       DATE '2026-03-01' - b.last_prior_unsub_dt    AS days_since_unsub,
       COUNT(*)                                     AS clients
FROM      mailed     m
LEFT JOIN unsub_in     i ON i.CLNT_NO = m.CLNT_NO
LEFT JOIN unsub_before b ON b.CLNT_NO = m.CLNT_NO
GROUP BY 1, 2, 3;

-- ORDER MATTERS. A client who left before the window AND again inside it is a LEAVER, not
-- already_out - the CASE tests unsub_in first. Reversing those two lines moves ~53,000 clients.
--
-- FLOOR CAVEAT. unsub_before starts at 2024-01-01, so "over a year" is bounded at ~26 months.
-- A client who opted out in 2022 and is still being mailed does not appear here at all: this
-- number is a FLOOR on the leak, not an estimate of it.

What I'd test next

Three things, each answerable, each with what it costs.

  1. Take the VRE leak to whoever owns that suppression list. 237,653 clients — 57% of the whole leak — left via one campaign and were mailed again at a median of 417 days. This is not an analysis question any more, it is an owner question. Costs a meeting, not a query.
  2. Size the silent population properly. 2,073,020 stayers opened nothing in three months, 30× the explicit unsub count. We have the data to profile them and do not report them at all. One analysis run, no new pull.
  3. Re-run L13 with the sampling guard. Solo rates above 500 per 1,000 are a small-campaign artefact of the 1-in-10 stayer sample, and the 1 / blank mnemonics are unmapped. Neither changes the verdict — the fix is so the table can be shown at all.
